# Vexa 0.2.2 自测报告

日期：2026-10-19。结论：**0.2.2 开发版增加全屏交互优化与统一播放控制，沿用离线安装包精简方案；Windows 打包程序完成全流程复测，尚未宣称完整 MVP 或跨平台正式验收完成。**

## 环境

- Windows 11 专业版，10.0.26200，x64。
- Intel Core i5-12490F、32 GB 内存、NVIDIA GeForce RTX 3060；同时存在虚拟显示适配器。
- Electron 44.9.0、Chromium 152.0.7977.167、内置 Node.js 24.22.0。
- 类型检查与构建使用 Node.js 24.21.0，TypeScript 严格模式。

## 全屏操作与统一播放面板

- 视频进度控件在普通窗口提供 28px 点击区域，全屏提供 34px；全屏悬停轨道增至 9px、拖动点为 18px。桌面流程使用真实鼠标按住和拖动，检查实际播放位置变化以及不会误触画面拖拽。
- 全屏播放约 2.8 秒无操作后隐藏工具栏、视频叠加控件和鼠标指针；鼠标移动唤醒。拖动、面板展开、键盘聚焦控制按钮、暂停与退出全屏时均保持或恢复可见。
- “双击放大”旁的按钮在下方展开局部面板，宽度 334px；普通窗口和全屏均验证位置、大小、点击外部收起、Esc 收起与焦点返回。全屏展开时视频区域尺寸保持不变。
- 统一进度实际作用于各视频；统一音量保留焦点发声策略；统一倍速更新各播放器。暂停状态下调节进度与倍速不会启动视频。不同视频时长、锁定、结束后拖回重播、后续新画面继承倍速、隐私静音和定时器清理由单元测试补充覆盖。

## 安装包精简

对比 0.2.0 已发布安装包与 0.2.2 最终构建，MiB 按 1,048,576 字节计算。

| 项目 | 0.2.0 | 0.2.2 |
| --- | --- | --- |
| Windows x64 离线安装包 | 159.70 MiB | 127.02 MiB |
| 完整应用目录 | 569.77 MiB | 479.16 MiB |
| 应用资源 app.asar | 44.95 MiB | 1.52 MiB |
| Electron 语言包 | 55 | 2（简体中文、英语） |

下载体积减少 **34,264,166 字节（20.46%）**；安装后占用减少约 90.61 MiB。清理重复的 Vue/Pinia npm 分发副本、sql.js 备用/调试/ZIP 构建和未使用语言资源，关闭尚未使用的差分更新压缩，采用离线 solid + BCJ2 压缩。

FFmpeg、FFprobe 与此前使用的二进制 SHA-256 一致；Electron 自带编解码库、软件渲染后备和许可证保留。未增加运行时联网下载。`npm run test:package` 实际定位安装器内嵌 7z 并通过完整解压/CRC 检查，同时检查必需文件和精简规则。此检查不替代真实安装、升级和卸载验收。

桌面和编码脚本显式指定独立 `--user-data-dir`，可与用户正在运行的旧版共存，测试只访问临时资料。

## 大视频库与资源控制

- 3,017 条索引：17 个实际测试文件（其中 1 个损坏）和 3,000 条仅用于浏览验证的种子记录。测试实际打开 SQLite、通过桌面 IPC 查询并渲染，未扫描 3,000 个真实媒体文件。
- 验证初始界面及末页均少于 60 张卡片，不随全库条目数同时创建全部卡片；按需页缓存上限 700 条由状态测试验证，选择集与随机池另行保存。
- 滚动到最后一条 `bulk-02999.mp4`，Shift 跨页选择及 Ctrl+A 均完整选中 3,017 条。1080P + 竖屏 + 失联筛选得到 1,500 条种子记录，验证分辨率按短边处理。
- 小、中、大缩略图切换改变卡片密度；大小设置与放大暂停设置重启后保留。900×700 窗口无横向溢出。
- 省资源模式暂停非主画面，退出时保留原有手动暂停；放大暂停与隐私隐藏也通过实际播放器状态检查。
- 掉帧识别使用真实解码累计计数差值，连续三个有效窗口掉帧率超过 5% 才提示；预热、暂停、计数重置与恢复由计数样本测试覆盖。本机未强制造成持续掉帧，不将该检查表述为真实高负载降级验收。

## 多路播放短测

样本为 1920×1080、30 fps、H.264 + AAC，本地生成的低复杂度风景画面视频。每组重新从头播放，记录开始与结束时的 `getVideoPlaybackQuality()` 差值。

| 同时播放路数 | 采样时长 | 总视频帧增量 | 丢帧增量 | 结论 |
| --- | --- | --- | --- | --- |
| 4 | 4 秒 | 477 | 0 | 各画面时间推进，无播放错误 |
| 9 | 4 秒 | 1080 | 0 | 各画面时间推进，无播放错误 |
| 16 | 4 秒 | 1920 | 0 | 各画面时间推进，无播放错误 |

这是播放链路的短时冒烟测试，**不等于 30 分钟稳定性或高运动/高码率视频性能验收**。未采集可靠的 CPU/GPU/显存占用，也未确认每路实际硬解方式；界面据此显示“硬件解码未确认”。不能外推为所有电脑的 16 路性能保证。

## 本机实际媒体样本

下列单片为 320×180、24 fps、5 秒的真实编码测试视频，并非仅依据扩展名或 `canPlayType` 推断。以视频已解码、有有效尺寸且时间推进为“可播放”。音轨为测试静音轨，没有进行音频听感校验。

| 容器与编码 | 本机结果 |
| --- | --- |
| MP4 / H.264 / AAC | 可播放，另完成 1080P 多路检查 |
| MKV / H.264 / AAC | 可播放 |
| WebM / VP9 / Opus | 可播放 |
| MP4 / HEVC 8-bit / AAC | 本机小样本可播放，不代表 HEVC 10-bit / 4K / HDR 已验证 |
| MKV / AV1 / Opus | 本机小样本可播放，软硬解方式未确认 |

## 自测中修复的问题

1. 跟随系统外观时，窗口已变化但页面媒体查询没有可靠通知：增加主进程到界面的外观事件，验证系统深浅变化。
2. 安全权限默认拒绝导致整墙全屏被拒绝：仅为应用自己的主窗口授予全屏权限，其他权限继续拒绝。
3. 全屏容器未随状态扩展：接入 `fullscreenchange`，确保播放区域占满可用空间。
4. 隐私隐藏后缺少便捷恢复入口：最小化到任务栏；恢复仍显示遮罩，保持暂停与静音。
5. 清理缓存时旧队列仍可能重写：中止当前封面进程并使旧扫描的缓存代次失效。
6. 倍速会影响自动换片计时：按倍速换算已播放墙钟时间，避免 2 倍速导致定时器提前一倍。
7. 打包工具缓存发生跨磁盘重命名失败：打包包装脚本默认使用项目内 `.cache/electron-builder`；标准打包命令复测成功。
8. 连续扫描进度可能反复推迟列表刷新：改为节流刷新，更新时保留已有卡片和滚动位置，忽略过期查询结果。
9. 多选原先只覆盖已加载条目：支持跨页区间和全库筛选结果选择；查询变化时取消过期选择提交。
10. 全局暂停会覆盖“播放结束”状态：保留结束状态，重新播放时正确回到开头，并避免降级仍在播放的画面状态。
11. 旧视频播放请求失败可能覆盖当前媒体错误：核对请求、媒体 ID 与实例，并保留具体编码错误提示。
12. 卡片内按钮的键盘事件可能触发卡片播放：限定卡片自身按键处理，键盘收藏复测通过；封面失效时显示占位图。
